## 4. Visual system and responsive design
Light aesthetic leads: warm parchment/ivory surface, subtle CSS texture or optimized external texture, forest green headings, near-black green text, muted gold borders/dividers and watercolor olive leaf clusters in outer corners. Dark: green-charcoal ink background, warm ivory headings/prose, muted gold linework, olive foliage; not pure black or saturated neon. Prismatic assistant buttons remain distinctive in both themes. Use tokenized CSS custom properties; initial approximate palette (not mandatory exact values): light bg #F8F3E7, surface #FFF9EE, heading #285044, text #202E29, gold #A88B48; dark bg #171D19, surface #202820, heading/text #F3E8D1, line #B99A5C. Adjust for contrast rather than forcing mock colors.
Use elegant literary serif for brand, headings, story titles and hero; readable system sans for UI/body; restrained italic accents only. Body copy >=16px, line height ~1.5–1.65. Use predictable consistent heading scale; 15–20% more section breathing room than compact mock; generous gutters, aligned cards, coherent borders/radii and restrained shadow. Gold is ornamental, not low-contrast small text. No visual ornament obscures content, controls or focus.
Re-use external approved art and existing CSS/SVG fracture/button patterns; create restrained scalable botanical/corner assets with CSS/SVG or approved optimized images, not embedded base64 or screenshots. Avoid direct franchise iconography or unrelated generated art. Images maintain aspect ratio, alt where meaningful, decorative motifs aria-hidden; reserve dimensions and use responsive sizing/lazy load below-fold. Ensure text in DOM, not baked into images. Preserve lightweight payload and no external font/API requirement.
At phone widths: masthead/nav wraps sensibly, hero uses deliberate crop and legible overlay text, assistant buttons stack or fit as a pair without truncation, Getting Started before examples, then feature and sample cards stack, footer reflows. No horizontal overflow at 320 CSS px; test common phone/tablet/desktop widths and 200% zoom. Prefer touch targets >=44px. Use reduced-motion, keyboard focus, high contrast and persist theme using existing preference handling where supported.

## 5. Story sample reading window (approved)
Click Read Sample or clearly interactive story card to open a large CSS/SVG modal reading window, not a separate reading platform. Prefer native dialog/showModal where compatible, or equivalent robust accessible modal. One reusable component driven by sample data.
- Backdrop dims site; panel centered, ~min(960px, viewport minus gutters), max-height ~90dvh, subtle short fade/rise; lock underlying body scroll without layout jump, pause slideshow, suppress motion for reduced-motion. Light parchment paper/forest headings/gold hairline ornament; dark ink/ivory/gold. Subtle SVG botanical corners, centered small gateway emblem, decorative divider; no illustration/texture behind prose that reduces legibility.
- Top bar: story title, "Sample Chapter" label, genre tags, clearly labeled Close (X), optional short synopsis. Keep close visible while scrolling. Chapter heading uses actual title/number. Estimated reading time optional and computed only if desired.
- Reading area: complete approved introductory chapter (normally Chapter 1), not invented/truncated placeholder. Semantic article, paragraphs and scene breaks preserve actual prose/formatting. One comfortable centered column (~65–75 characters or 65–70ch), literary reading serif ~18px desktop, 1.65–1.8 line-height, paragraph spacing; visible single vertical scroll region, no nested horizontal scroll. On small screens near-fullscreen sheet, simplified frame, accessible sticky header/actions and adequate content viewport.
- Footer/action area: "Download Manuscript" links to actual approved full manuscript asset, label file type (and size if known), "Close". Optional next/previous sample navigation only if straightforward; omit for initial implementation unless clear value. Read Sample is primary on homepage, download secondary. Download should work from overlay; no competing duplicate CTA required on homepage. File format use existing verified Markdown or PDF (do not fabricate PDF or unavailable chapters); preserve chapter numbering/titles and manuscript bytes. If unavailable, omit/disable with explicit "Manuscript not yet available"; never broken/fake download.
- On open, move focus appropriately (heading or close), trap focus, keep underlying site inert; close via X, Escape, backdrop only when actual backdrop clicked, or footer Close; return focus to originating card/button and restore scroll/slideshow state without overriding user pause. Prevent overlapping About/Guide/launch/sample dialogs; keyboard access including Tab/Shift+Tab and screen reader accessible name. If content loading fails, readable error, retry/close, no indefinite spinner. No comments, bookmarking, accounts, chapter navigation catalogue, reading progress tracking or hosting other users' stories.
